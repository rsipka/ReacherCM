# Changelog

All notable changes to Reacher CM are documented here. Reacher CM is a personal fork of [Reach](https://github.com/alexandrosnt/Reach) with additional features, written with the help of AI coding tools; the entries from v0.9.1 down are Reach's own.

## Reacher CM (unreleased, based on Reach v0.9.2)
- **More RDP settings, like Remote Desktop Manager** — The RDP session editor has a new *Display, keyboard and performance* section: a fixed *Desktop size* (scaled to fit the window) instead of following the window, *Display scaling*, *Colours* (32 or 16-bit), the *Keyboard layout* the remote starts with, *Remote sound* on or off and its quality, *Visual effects* (balanced, fastest or best looking), *Keep alive* and a *Mouse jiggler* (so firewalls and screen locks leave an idle session alone), *Compress data*, *Connect to the console (admin) session* and *Start a program instead of the desktop* (with its start folder). On a high-DPI screen the remote desktop now uses the screen's scaling by default (200% on a 200% screen) instead of 100%, where text was tiny; resizing keeps it. Phones and tablets keep 100% unless set. Sessions opened in FreeRDP get the same size, scaling, colours, keyboard, sound off, effects, compression, admin and program settings. Unset, every session connects as before. In all 10 languages. Not yet tried against a real server.
- **ZMODEM: no protocol bytes left in the terminal** — After `rz` or `sz`, the terminal could show leftovers of the protocol: a `*`, a `�` at the start of the line and the shell prompt written over "rz waiting to receive.". The line `rz`/`sz` prints is now cleared when the transfer starts (the bar over the terminal shows what is happening), and the end of the last ZMODEM header (CR, LF, XON, "OO"), after an upload, a download or a cancel, is no longer shown, so the prompt comes back on a clean line.
- **tmux windows in a new tab from the terminal bar** — In the terminal bar's tmux dropdown, each window now has an *Open in new tab* button beside it, and so does *New window*. Ctrl+click (⌘+click on a Mac) or a middle click on a window does the same. The new tab shows that window of the same tmux session, as *Open in new tab* in *tmux windows…* does. Not yet tried in the real app.
- **FTP, SFTP and SCP sessions** — The session editor's *Transfers* tab has three new session types that open straight in the full-pane file manager, with no terminal. *SFTP* and *SCP* are SSH sessions underneath, so saved credentials, keys, jump hosts, proxies and password managers work as for SSH; SCP sessions never use the SFTP subsystem (listings use shell commands, files go over the scp protocol), for servers that offer only scp. *FTP* is a new connection type with explicit FTPS (AUTH TLS, the default), implicit FTPS (port 990) or plain FTP, passive mode only. An unknown server certificate shows its SHA-256 fingerprint to trust once for the session, and the session list shows an FTPS, FTP, SFTP or SCP badge. Desktop only. Tested against vsftpd (explicit, implicit, plain), pure-ftpd and OpenSSH scp; not yet tried in the built app.
- **Connect to another address or with another login from the session menu** — The session's right-click menu (long press on a phone) now has one *Connect to…* item instead of the separate *Connect via* and *Connect with* lists, which made the menu long. It opens a page in the menu with the session's addresses (*Automatic* first when the session picks one by itself, else the one used last) and its logins (the session's own, then the saved credentials of its vault), then *Connect*. Any address goes with any login, so an SSH session can now connect to its office address with another credential in one go. The address part is for SSH sessions with other addresses; Telnet and RDP sessions get the login part. A session that starts in tmux (its own setting or its folder's) also gets *Connect without tmux* in the menu, and a *Without tmux, this once* switch on that page: a plain shell for one connect, the setting is unchanged. In all 10 languages. Not yet tried in the real app.
- **Saved host keys no longer lost by sync** — A host key saved on a session could disappear when another device saved the same session from a copy that did not have the key yet (not synced, or an older build), because the newest copy replaced the whole session. Sync now merges the saved host keys of both copies, keeping the newest key for each server, and sends the merged session back out. A key you remove (in the session editor or with *Remove all saved host keys*) is remembered as removed, so a device that still has it does not bring it back. Quick Connect and RDP keys, and sessions that use OpenSSH `known_hosts` files, stay on each device as before.
- **tmux in the terminal bar, and a session picker there** — The terminal bar of an SSH tab in tmux now names its tmux session and the window it shows (`tmux web-01 · htop`) instead of a plain *tmux* badge. Click it for a dropdown of the server's tmux sessions (windows, how many are attached, the current one ticked): pick one to switch the tab to it, or type a name to start a new one. A tab in its own view also lists the session's windows there, to show one or open a new one. Same as *Switch tmux session…* and *tmux windows…* in the tab's menu, one click away. On a phone the bar shows just *tmux* and the arrow. In all 10 languages. Not yet tried in the real app.
- **tmux sessions named `reachercm-…`** — The tmux sessions the app names by itself are now `reachercm-<session name>` instead of `reacher-…`. A session started under the old name is not left behind: while the server has it and no `reachercm-…` one, connecting goes back to the old one (and keeps using it). A name you typed in the session editor is unchanged.
- **Virtual consoles open from web sessions** — Launching an iDRAC's HTML5 virtual console from a *Web* session was blocked as a pop-up, with no way to allow it: the console button asks the device for a session first and opens the window afterwards, and the web engine (on Linux and macOS) only lets a page open a window straight from a click. Web session windows now let the page open its windows; they open as more windows of the same session, with its cookies and trusted certificates, and still cannot reach the app. A new *Allow pop-up windows* switch in the session editor (on by default) turns this off per session.
- **Folders for saved credentials** — The *Credentials* tab can now keep credentials in folders. The folder button beside *New credential* makes one; right-click a folder (or its ⋯ button) for *New credential here*, *New subfolder*, *Rename*, *Icon…* (the same icons and colours as session folders), *Move to folder…* and *Delete folder…*. Right-click a credential for *Move to folder…*, drag it onto a folder with the mouse, or pick its folder in the credential editor. Folders open and close with a click and show how many credentials are inside; the app remembers which are closed. Deleting a folder deletes nothing inside it: its credentials and subfolders move up a level. A folder lives in the vault of its credentials and syncs with them, and holds only credentials of that vault. The session editor's *Login* list now groups credentials by folder. Folders are only for order: a session's login is still chosen as before. An older version does not show the folders, and a credential it saves goes back to the top. In all 10 languages. Not yet tried in the real app.
- **Transfer queue and easier Compare in the full-pane file manager, and Open file manager from the session menu** — Copies and moves (F5, F6, the middle arrows, the right-click menu) now join a *Transfer queue* under the panes instead of blocking the file manager: they run one at a time per connection, so you can keep browsing and adding more while one runs. Each item shows its direction, name, progress or result; a waiting one can be dropped, the running one cancelled, and a failed or cancelled one tried again. *Clear finished* empties the done ones, and the list folds away. Moves delete the source only after the copy succeeded. Closing the connection empties its queue. *Compare files* is now easier to reach: two buttons in the middle column (*Compare files* and *Compare folders*), an item in the empty-space menu, and a *Compare with* item for any file that has a partner. That partner is the file of the same name on the other side, or else the file under the other cursor. Two files marked in one pane compare with each other. Right-clicking an SSH session in the session list now offers *Open file manager*: it switches a connected tab of that session to the full-pane file manager, or connects and opens it there. Desktop only. In all 10 languages. Not yet tried in the real app.
- **GNOME Remote Login from phones** — Connecting from the Android or iPhone app to a GNOME machine with *Remote Login* failed with a CredSSP error after GNOME handed the connection over to its login screen. GNOME gives phones the one-time password for that hand-over in a different form than desktops, and the app kept logging in with your own password. It now logs in with the handed-over one, as FreeRDP does.
- **Session types grouped in the session editor** — The editor's protocol choice now has two rows: first the kind, *Terminals* (SSH, Telnet, Serial, WSL) or *Remote desktop* (RDP, VNC, SPICE) or *Other* (Web, WinBox), then the protocols of that kind. Picking a kind switches to its first protocol. A *Transfers* kind is ready for file transfer protocols and shows once there are some. The editor also keeps one height whatever the protocol (at most 880 px, or 85% of the window), so switching protocols no longer resizes it and moves its headers, and its scrollbar no longer shifts the columns sideways. In all 10 languages. A Web session no longer shows terminal colours, cursor and history choices, which it never used. Not yet tried in the real app.
- **Right-click menus in the full-pane file manager** — Right-click a file or folder in either pane (this computer or the server) for *Open*, *View*, *Edit*, *Edit in Reacher CM* (server files), *Copy* and *Move* to the other side, *Rename*, *Delete*, *Compare with* the file under the other pane's cursor, *Copy path* and *Copy filename*, plus *CD here* for a server folder and *Show in file manager* for a local one. With several files marked, right-clicking one of them acts on all of them. Right-click empty space for *New folder*, *New file*, *Refresh*, *Select all*, *Compare folders*, *Copy folder path*, and *Go to the terminal's folder* / *CD the terminal here* (server) or *Home folder* / *Show in file manager* (this computer). The menu key or Shift+F10 opens the menu for the row under the cursor. Each item shows its F-key.
- **ZMODEM: buttons, folders** — Two arrows on the terminal bar of SSH, Telnet and serial tabs, and three items on the tab's right-click menu. *Send files* and *Send folder*: pick them, and the app types `rz` on the other end and sends them as soon as it answers; a folder goes with everything in it and `rz` recreates its subfolders. *Download this folder*: pick where to save, and the app types a `find … -exec sz -f` line that sends every file under the shell's current folder, subfolders included (in a subshell, so the shell stays where it was; a POSIX shell such as bash or zsh). Downloads now keep the folders the remote names (`sz -f dir/x`) under the folder you picked, never above it; existing folders are reused and existing files still never overwritten. Names starting with a dot keep it. If `rz` or `sz` does not answer within 20 seconds, the app says lrzsz may be missing there. Empty folders are not copied. Desktop only.
- **Tunnels through saved SSH sessions** — Pick a saved SSH session for each local forward or SOCKS proxy. Start opens a dedicated SSH connection using the session's saved login and route without opening a terminal tab. Stop or Remove closes that connection and releases the local port.
- **GNOME Remote Login over RDP** — A GNOME machine with *Remote Login* turned on (the login screen over RDP) now gets past the first step: the app follows GNOME's hand-over to the login screen and later to your own session, instead of stopping with *decode error* two seconds after connecting. GNOME sends that hand-over in a form the RDP library rejected, and the session it hands you to wants a login step called RDSTLS, which the app now does the way FreeRDP (and so Remote Desktop Manager) does it. GNOME *Desktop Sharing* is unchanged.
- **FreeRDP on X11** — Reuses certificates already approved in IronRDP and reports certificate failures instead of waiting for a console prompt.
- **SSH key passphrases with Windows Hello and macOS Touch ID** — Under Settings > Security > *Unlock credential keys at start*, opt in to remembering the passphrases you type for saved credential keys. On the next vault unlock, one Windows Hello or Touch ID prompt unlocks the remembered set. Windows Hello may offer its PIN. macOS requires a build with access to the Data Protection Keychain. The saved passphrases stay encrypted on this device, outside vault sync and export. Cancel to type them as before, or turn off the setting to forget them.
- **FreeRDP for saved RDP sessions** — On desktop, choose *FreeRDP (separate window)* in the session editor to connect with a locally installed FreeRDP 3 client. Settings > Remote desktop shows the detected executable and lets you choose another. Saved passwords are passed through a private pipe. Existing sessions and mobile continue to use the built-in IronRDP client by default.
- **Forward lock key presses in RDP sessions** — The session editor now has a *Forward lock key presses* option, enabled by default. It sends Caps Lock, Num Lock and Scroll Lock presses to the focused desktop so remote shortcuts can use them, then syncs the lock state after release. Turning the option off keeps lock state synchronization active. Changes apply the next time you open the session.
- **Wider session editor with two columns** — With the many session types, the protocol buttons at the top of the session editor were cut to *S…*, *V…*. On a window at least 1000 px wide the editor is now about 940 px wide: every protocol fits on one row, and the settings sit in two columns, *Connection* (name, address, login, jump host, proxy, SSH options) on the left and *Terminal & organising* (tags, OS icon, folder, colours, cursor, history, terminal type, encoding, tmux, notes) on the right. In a narrower window the editor is one column as before, but the protocol buttons wrap into rows instead of being cut. The remote desktop button is now *RDP* (the full name shows on hover). On a phone the editor fills the screen. In all 10 languages. Not yet tried in the real app.
- **Terminal type, Backspace key and encoding for SSH sessions** — The SSH session editor's terminal settings (under the cursor and history choices) now have *Terminal type* (what the server is told the terminal is, `TERM`: xterm-256color as before, or vt100, vt220, linux, screen-256color and others, or anything typed in), *Backspace sends* (DEL, as before, or Ctrl+H for devices that expect ^H), and *Encoding* (UTF-8 as before, or ISO-8859-2, windows-1250, windows-1251, windows-1252, KOI8-R, Shift_JIS, GBK, Big5 and other legacy character sets: the server's output is shown correctly and what you type and paste is sent in that encoding; a character it lacks goes as `?`). They apply from the next connect, also through jump hosts, and sync with the session. Session log files stay UTF-8 whatever the encoding, and their header and pause/resume lines now say *Reacher CM log* instead of *Reach log*.
- **Open sessions stand out in the session list** — A session with a tab open now has a light tint in the session list, and the session of the tab on screen (the focused pane in a split) is shown as picked, following you as you switch tabs. A small green dot beside the name says that one of its tabs is connected: an SSH, Telnet or serial tab that is up, a remote desktop (RDP, VNC, SPICE) once its desktop shows, or an open WSL tab. A tab that is connecting, dropped or reconnecting keeps the tint without the dot. Works with every theme and in Compact layout. A tab moved to a floating window is not counted. Not yet tried in the real app.
- **Long press a session on a phone for its menu** — On phones and tablets, holding a finger on a session (or a folder) now opens the same menu a right click opens on desktop: *Connect via* another address, *Connect with* another saved credential, Edit, Clone, favourites, history, moving and deleting. On a phone it comes up from the bottom of the screen as a sheet, titled with the session's name, with rows sized for a finger, covering at most about half the screen (the rest scrolls); a tablet shows it at the finger. Lifting the finger does not also connect, a press that turns into a scroll opens nothing, and a short tap still connects as before. Not yet tried on a real phone.
- **Remote desktop: held keys repeat, lock keys follow yours** (from upstream PR #180) — Holding a key in an RDP session typed it only once; the app now sends each repeat, as mstsc does. NumLock, CapsLock and ScrollLock on the remote now mirror your keyboard, as in mstsc and RDM: they are set when the session connects, when you come back to its tab, and whenever you press a lock key, in every open RDP session at once, so the keypad no longer types arrows instead of digits and switching tabs keeps the state you set. On Linux, where the app's web view cannot see NumLock, it is read from the keyboard's LED (and from what the keypad types). A Mac keyboard has no NumLock, so it counts as on. VNC and SPICE are unchanged. Also from that PR: cancelling every open password manager question at once could leave one unanswered for a moment. Not yet tried against a real Windows server.
- **System theme with a light and a dark theme of your choice** — Picking *System* in Settings > Appearance now shows a *Light theme* and a *Dark theme* picker: the app uses the first while your computer is in light mode and the second while it is in dark mode (for example Catppuccin Latte by day and Tokyo Night by night). Each lists the themes of its own kind, installed ones included. The app now also follows the computer the moment it switches, instead of at the next start. Going to *System* from a theme you picked by hand keeps that theme as its half of the pair. Unset, the pair is Reacher CM Light and Dark, as before; a theme removed from the pair falls back to them. The setup wizard's *System* card shows the pair. In all 10 languages.
- **11 colourful app themes** — New built-in themes with tinted backgrounds and a strong accent: Ocean, Forest, Sunset, Amethyst and Cherry, each in a dark and a light version (natural pairs for *System*), plus Neon Night. They are under *More built-in themes* and pass the same contrast checks as the others.
- **Folder icons** — A session folder can now have an icon of its own instead of the plain folder: right-click a folder (or its ⋯ button) and pick *Icon…*. Choose from about 90 symbols (server, database, cloud, network, firewall, house, office, lab, rocket and more) or a logo (the OS logos plus Docker, Kubernetes, Proxmox, VMware, TrueNAS, Synology, pfSense, OPNsense, OpenWrt, Cisco, Fortinet, MikroTik, UniFi, cloud providers and others), with a search, and one of 14 colours (or the theme's). The icon shows in the session list and in the *Move to folder* lists. *Plain folder* and *Theme colour* go back to the default. The icon and colour are part of the folder's record, so they sync with its vault; an older version that changes the folder (rename, move) drops them. In all 10 languages.
- **Password history** — Changing the password of a session or a saved credential now keeps the old one. The session editor (and the credential editor) shows *Previous passwords (N)* under the password field when there are any: each with the date it was replaced, hidden until you press its eye, *Copy*, and *Use*, which puts it back in the field (saved with the rest of the form; the current password then moves into the list). *Clear history* forgets one session's list. Old passwords are part of the session's own record, so they are encrypted in its vault and sync with it, and are read only when the editor shows them, never with the session list. Settings > Security > *Password history* sets how many each session keeps (*Off*, 3, 5, 10, the default, 20 or 50; a lower number trims the list on the next save), and *Clear all password history* forgets them everywhere, shared vaults included. Only typed passwords are kept, not password manager entries or key passphrases. An older version that saves the session drops its history.
- **A different jump host for each address** — Each extra address of a session now has a *Route*: the session's own jump hosts or proxy, *Direct*, or *Through* another saved SSH session. Through a saved session, the connection goes over that session's jump hosts and then that session's server, logging in as it does, so one gateway session can serve the addresses of many servers (an office address direct, a branch office through its own gateway, the internet address through the main gateway). Automatic, *Connect via*, the picker and reconnect all follow the address's own route, and the terminal bar shows the hops used. A gateway session that logs in with a password manager entry cannot be used this way yet (its entry is its own); save its password in it, or use a key or the agent. The route is part of what a session's password manager entries are approved for.
- **X11 desktop sessions** — An SSH session can now open a whole Linux desktop instead of a shell, as uniTerm's X11 Desktop does: the session editor's new *X11 desktop* choice starts GNOME, KDE Plasma, Xfce, MATE, Cinnamon, LXQt, Openbox or a start command of your own on the server, and shows the desktop in one window of its own here. That window is a separate X server started for the session alone: Xephyr on Linux (install `xserver-xephyr` or your distribution's Xephyr package), the X11 server from Settings > General in a single window on Windows, and XQuartz on macOS (or Xephyr, if installed). Because that X server holds nothing else, the desktop gets full (trusted) X11 access without seeing any other window on your computer; its cookie stays here, as with any X11 forwarding. Closing the tab closes the window, and the desktop's messages show in the tab. The server needs `X11Forwarding yes` in its sshd_config and xauth installed; the tab says so when either is missing, or when the desktop is not installed. Desktop apps only; the session list marks these sessions *X11*. Tried against an SSH server with Openbox on Linux; not yet tried on Windows or macOS.
- **Connect with another saved credential** — Right-click an SSH, RDP or Telnet session and pick a saved credential under *Connect with* to connect once with it, without changing the session: its own login (or the credential linked to it, shown ticked) stays as it was, and nothing typed in the connect prompt is remembered for it. The list shows the session's vault's credentials with their user names; RDP and Telnet list those with a password. A credential whose secret is a password manager entry cannot be used this way, since entries are approved per session (link it in the editor instead), and neither can another user name for a session whose jump hosts or proxy use password manager entries; the menu says why.
- **SSH tab tooltip shows the algorithms in use** — Hovering a connected SSH tab now shows, under its title, what the connection's key exchange settled on: the key exchange, the server's host key type, the cipher, the MAC (or *built into the cipher* for AES-GCM and ChaCha20-Poly1305) and compression. A MAC or compression that differs each way shows both, outgoing first. A tab sharing another tab's connection (ControlMaster) shows its title only. In all 10 languages.
- **Session tooltips show the other addresses themselves** — The tooltip of a session with several addresses listed only the names of the others (*Also: Office, VPN*). It now shows each with its host or IP beside it (*Also: Office (10.0.0.5), VPN (10.8.0.5:2222)*); an address without a name shows just the address, as before.
- **Quick command history** — A small, fast list of the commands you ran before, to paste one into the terminal without the full *Session history* window. Press Ctrl+Shift+R (⌘⇧R on a Mac; changeable in Settings > Keyboard shortcuts) in a terminal, or pick *Command history…* in the terminal's or the tab's right-click menu or the command palette. It lists each command once, newest first, with how often and how long ago it ran, a red mark when it failed, and where it ran; typing filters it. ↑↓ (or Ctrl+N / Ctrl+P, or Ctrl+Shift+R again) move, Enter pastes the command into the tab without running it, Ctrl+Enter pastes and runs it, Ctrl+C copies it, Esc closes. A tab opened from a saved session starts with that session's commands; Tab or the button beside the search switches to all sessions. *Full history…* opens the full search for output and whole runs. The shell's own Ctrl+R is left alone. Needs session history turned on. In all 10 languages.
- **Web sessions, with sign-in** — A new *Web* session type opens a device's management page (Dell iDRAC, HPE iLO, Proxmox VE and Backup Server, UniFi, a switch, a PDU) from the session list. Paste the whole address into *Address* (`https://10.0.0.5:8006/`) or give host, port, protocol and path. The page opens in a window of its own, kept away from the app: it cannot call any of the app's commands (no permission covers web windows, and the app also turns away every request from them, whatever page they show), it cannot leave http/https for the app's own pages or local files, and it keeps its cookies and storage apart from the app and from every other session. Under *Cookies and saved logins*, sessions can instead share a named profile (the nodes of one cluster), or forget everything when the window closes; *Clear cookies and storage* empties a session's. *Sign in* types the session's user name and password (from the vault, a saved credential or a password manager) into the page's login form and presses the login button: *Automatic* knows iDRAC 7/8/9, iLO 4/5/6, Proxmox and UniFi pages and otherwise uses the first password field; each preset can be picked by hand, *My own field selectors* takes CSS selectors, and *Off* only opens the page. The password goes into the page only when the page is on the session's own address (scheme, host and port), the button is pressed once per window so a wrong password never loops, and an HTTP login prompt (Basic or Digest) from the same server is answered once. A certificate your system does not trust, as on most iDRACs and Proxmox hosts, is not accepted globally: the app asks once, showing its SHA-256 fingerprint, and *Trust for this session* keeps that fingerprint on the session (it syncs with it); a different certificate later is asked about again, with a warning that it changed. The editor lists the trusted certificates with *Remove*, and a fingerprint can be pasted in before the first visit. A page that opens a window (a virtual console) opens another window of the same session. *Open in: The system's browser* opens the address in your browser instead, without sign-in. Desktop opens its own window; phones and tablets open the browser. Presets are best effort and not yet tried on real devices; macOS certificate handling not yet tried on a Mac.
- **ZMODEM file transfer (rz/sz)** — Type `sz file` on the other end of an SSH, Telnet or serial session and the app asks where to save it (the folder picked last time is offered first); type `rz` and it asks which files to send. Several files go in one go. A bar over the bottom of the terminal shows the file, how much is done and the speed, with *Cancel* (Ctrl+C in the terminal does the same); keys typed meanwhile are held back so they cannot corrupt the transfer. Downloads never overwrite: a name already taken is saved as `name (1).ext`, a name the remote sends with folders or `..` in it is reduced to the bare file name, a cancelled or failed download is removed, and files keep the time the remote gives them. Everything else on the line passes through untouched. Meant for gear without SFTP: serial consoles, switches and routers over Telnet, small hosts with only a shell. Over Telnet the data goes through Telnet's own escaping (IAC, CR NUL), not the session's Enter and Backspace settings. Files up to 4 GB (ZMODEM's limit). Desktop only. Built on the [zmodem2](https://codeberg.org/jarkko/zmodem2) crate (MIT/Apache-2.0).
- **Compatible SSH reaches servers with 2048-bit group exchange** — With *Compatible* or *Custom* SSH algorithms, an old server that answers the diffie-hellman group exchange with a 2048-bit prime failed with *DH prime size (2048 bits) not within requested range*, because the app asked for 3072 bits or more. A session that sets its own key exchange list now asks for at least 2048 bits, as OpenSSH does, and down to 1024 bits when 1024-bit *diffie-hellman-group1-sha1* is offered too. *Secure* keeps asking for 3072 and up.
- **Removing a jump host sticks** — Removing every jump host from an SSH session, or turning *Use jump host* off, and saving kept the old jump hosts: the editor fell back to the chain the session had before. Saving now clears them.
- **Remote desktop keeps its size when you switch tabs** — Switching away from an RDP tab and back made the remote desktop shrink and then grow to fill the tab again, which moved and resized the windows on it. A tab you are not looking at measured as zero size, and the app asked the server for its fallback size of 1024 × 768. A hidden tab, or a page you left, no longer asks the server for a new size; the desktop keeps the size it had.
- **SPICE sessions** — A new session type for the displays of KVM/QEMU virtual machines (Proxmox VE, libvirt and virt-manager, oVirt), next to RDP and VNC. A session has a host, port and password, an optional TLS port with the server's CA certificate and certificate subject, and can go through a saved SSH session as VNC can. *+ > Open SPICE file (.vv)* opens the file that Proxmox's SPICE console button or virt-manager hands out, through Proxmox's spiceproxy, without saving a session; a file that asks to be deleted after use (Proxmox's ticket works once) is deleted as virt-viewer does. Keys go by position as for RDP, so the guest's keyboard layout counts; the guest's clipboard (text) and resizing the guest to the tab need the SPICE agent (spice-vdagent) in the guest. Works on desktop and phones. Not yet: sound, USB redirection, shared folders, H.264 video streams (MJPEG streams work). Built on the protocol and image decoding of the ryll SPICE client (Apache-2.0).
- **WinBox 4 sessions** — A new session type, *WinBox*, opens a MikroTik router or switch in MikroTik's own WinBox 4 app (Windows, macOS, Linux), logged in with the session's user and password. It takes a host name, IPv4, IPv6 or MAC address, and a port when it is not 8291; saved credentials and password manager entries work as for other sessions. WinBox sessions show the MikroTik logo and open no tab here. WinBox is found by itself in the usual places (PATH, the download folders, Program Files, /Applications/WinBox.app, ~/.local/bin, /opt, Homebrew, Flatpak); Settings > Sessions > *WinBox 4* shows which one is used and takes another path. WinBox reads a password only from its command line, where other programs on the computer can see it while it runs, so Settings > Sessions > *WinBox password* offers *On the command line* (the default, logs in by itself), *On the clipboard* (copied for 45 seconds, to paste into WinBox) or *Not passed*. Desktop only. Not yet tried with a real WinBox.
- **Raspberry Pi OS detected** — SSH sessions to a Raspberry Pi running Raspberry Pi OS (Raspbian) now show the Raspberry Pi logo instead of Debian's. - **1Password** — Sessions can take their password from 1Password. Settings → Password managers has a 1Password card: install the 1Password CLI (`op`), turn on *Integrate with 1Password CLI* in the 1Password app, and pick entries from the key button next to any password field. The 1Password app asks you to approve access (Touch ID, Windows Hello or your password); Reacher CM stores nothing. A service account token can be used instead. Each connect reads the password with `op read`; nothing is cached.
- **Groundwork for more password managers** — The password manager code, so far written for Passbolt, now shares what any manager needs: finding and checking its command-line tool, the environment it runs with, and a question that can ask for a vault's master password as well as a key's passphrase. With it filled in, Reacher CM logs in to macOS Screen Sharing and Apple Remote Desktop with the Mac's own account instead of a VNC password, so a Mac no longer needs the legacy VNC password turned on. Reacher CM uses Apple's RSA + SRP login: the user name is sent encrypted, the password never leaves your computer, and the Mac must prove it knows the account before the login completes. The older Apple login (Diffie-Hellman), which anyone on the network path could read the password from, is used only through an SSH session or to localhost. As before, the screen itself is not encrypted unless the session goes through SSH. RDM import brings in Apple Remote Desktop entries as VNC sessions with their user name. Curtain mode and Apple's High Performance mode are not supported.

- **VNC desktops** — A new session type for VNC servers (TigerVNC, x11vnc, RealVNC with a VNC password, and others), drawn by the same panel as remote desktop: scaling, the cursor, full screen and the phone key bar come with it. The desktop is scaled to fit and never resized: a VNC desktop is usually shared, and resizing it to a phone's shape cut windows off for everyone watching. Keys are sent as the characters typed, so the local keyboard layout is the one that counts. Tested against TigerVNC on Windows and Android, directly and through SSH.
- **SSH session logging** — Settings → Appearance → Session logging writes each SSH session to a text file, the way PuTTY's Logging panel does. "Printable output" keeps the text and drops colour and cursor codes (through vte, the terminal parser Alacritty uses, so a code split across two packets is still caught); "All session output" keeps everything sent to the terminal. File names take PuTTY's &H &P &Y &M &D &T, and a host name can never add a folder or a drive to the path. Logs go to Documents/Reach Logs unless another folder is chosen, are added to rather than replaced unless asked, start with a date line, and are written as the output arrives. Only output is logged, never keystrokes, and on Linux, macOS and Android a new log can be read by its owner only. If a log cannot be opened the session still connects and says it is not being logged. Off by default.
- **Nothing typed into your shell by default** — Reach used to type a colour and prompt setup into the shell after every login, and bash saved those lines in ~/.bash_history. Like PuTTY and OpenSSH, Reach now types nothing: servers colour their own prompt and ls for its xterm-256color terminal, and true colour is announced with an SSH environment request (COLORTERM=truecolor) instead of a typed export. The setup can be switched back on in Settings → Appearance; it now starts every line with a space and keeps itself out of history (tested in bash with seven history settings, zsh, dash, mksh, BusyBox and fish). The one case left is zsh with a history file and without HIST_IGNORE_SPACE, which keeps a single line.
- **A session tries only what it names** — A session with its own key offers that key, a password session its password, an agent session the agent's keys; nothing else. Reach used to offer every key in the SSH agent (or Pageant) behind a refused session key, and the agent's keys before a password. Each refused offer counts against the server's MaxAuthTries and its brute-force protection (OpenSSH's PerSourcePenalties, fail2ban, firewalls block the address after a few), every key offered tells the server who you are, and a session whose own key no longer worked kept working on a PC with an agent and failed everywhere else. This is what PuTTY does (its userauth2-client.c filters Pageant down to the configured key) and OpenSSH with IdentitiesOnly. A session can still offer the agent's keys behind its own: Edit session → "Also try my SSH agent's keys if this key is refused". If a session that used to connect now says its key was refused, the agent was covering for it: put the session's public key in the server's authorized_keys.
- **A refused key says which key** — The message names the key by its SHA-256 fingerprint, the one ssh-keygen -lf prints for authorized_keys, instead of a general "authentication rejected".
- **Imported keys are exactly what was imported** — A key is stored byte for byte as the file held it, so every device and every backup has the same bytes; reading it is what is forgiving, so a key with Windows line ends, trailing spaces or a byte order mark logs in instead of failing as "passphrase-protected". The public key shown for a key is now always derived from the private key, as ssh-keygen -y does; a .pub file beside the key that belongs to another key is no longer shown in its place. A backup round trip is tested byte for byte.
- **Importing ~/.ssh/config no longer hangs** — A host name that appeared in more than one Host block was listed twice, and the import dialog stopped on loading; it is now one host, its settings combined first value first, as OpenSSH reads it. A config saved with a byte order mark (PowerShell 5 writes one) lost its first host; it no longer does.
- **Host keys on your own time** — Checking a new server's fingerprint no longer has to happen within the 15-second connect limit, and the question closes when its connection is gone instead of staying up to be accepted for a connection that no longer exists. No answer is a no, as before.
- **Vault reset removes its key** — Resetting the vault now also removes the identity's key from the OS keychain. Restoring a backup leaves the previous identity's key where it is, as a way back.
- **A Mac window with Mac buttons** — On macOS the window now has the system's own close, minimise and zoom buttons at the top left, over Reach's title bar, instead of Reach's Windows-style buttons on the right. Dragging the bar moves the window and double-clicking it zooms, as in any Mac app.
- **No more "Not connected" under a remote desktop** — The SSH stats bar is not shown under RDP and VNC desktops, where it said "Not connected" about a desktop that was connected.

## v0.7.0
- **Lock Reach** — Settings → Security has Lock now, auto-lock after 1 to 60 minutes without keyboard or mouse use, and a switch to lock when the computer locks or goes to sleep (Windows session lock and suspend, macOS screen lock and sleep, Linux logind and the desktop screensaver, as KeePassXC watches them). A test scans the process's own memory and finds the plain key when it is held the old way, and nowhere once shielded.

SQLite goes through the libsql Reach already carries for the vault: sqlx's own SQLite bundles a second copy of SQLite, and two in one binary collide at link time (tursodatabase/libsql#541).

MariaDB is told apart from MySQL by the greeting the server sends first. A database found this way connects through that tab's live connection, with no second login.
- **Nothing runs unseen** — The editor, the grid and the designer all turn into SQL, and all of it is shown before it runs. A script is split and read before anything is sent: `DROP`, `TRUNCATE`, and `UPDATE` or `DELETE` without a `WHERE` at the top level are held back with the reason, and a `WHERE` inside a subquery does not count. A connection marked *production* holds back every write and asks for its name on a destructive one; a *read-only* connection refuses writes in Reach and, on PostgreSQL, MySQL, MariaDB and SQLite, in the server session too. The splitter knows strings, quoted names, comments, PostgreSQL dollar quotes, MySQL `DELIMITER`, `BEGIN … END` bodies of MySQL and SQLite routines and triggers, and SQL Server `GO` batches, so a procedure is never cut at its first semicolon. Grid edits are written as literals rather than bound parameters on purpose: the literal is what the review shows, and a text parameter is refused by a PostgreSQL integer column where a literal is converted. They run in one transaction, and an update that matches no row, because someone changed it meanwhile, rolls the lot back.

- **Stop means stop** — Each query tab has its own server session, so a transaction or `SET` in one stays in it, and each session records its server-side id when it opens. Stop is sent from another session: `pg_cancel_backend`, `KILL QUERY`, or on SQL Server `KILL`, after which the tab reconnects on its next use. The server monitor lists sessions with their running statements and can cancel a query or end a session, and marks Reach's own.

An editor per type — strings, hashes, lists, sets, sorted sets, streams — sending each change as arguments, so a value with spaces or quotes needs no escaping. ## v0.6.6
- **Remote desktop over RDP** — A Windows desktop in a tab, next to the shells. The protocol is IronRDP, which is pure Rust from the TLS handshake and CredSSP through the bitmap codecs, so it builds for Windows, Linux, macOS and Android alike with no native RDP library and no C toolchain. Pixels reach the webview as raw bytes over a Tauri channel rather than as JSON events: a full 1080p frame as a JSON event would be eleven megabytes of base64, and a loopback socket, the other way to avoid that, would have needed a listener, a CSP exception and a cleartext allowance on Android. Open one from **+ → Remote desktop (RDP)**, or save it: the session editor has a protocol row, and choosing RDP moves the port to 3389, shows only password and domain, and keeps keys, agents, jump hosts, proxies and login shells out of the way because they are SSH ideas. Saved RDP sessions get a Windows glyph, drawn by hand since Simple Icons carries no Windows mark.
- **Whole frames, not a mosaic** — The first version painted every changed tile the moment it arrived, and a video looked like every laggy remote desktop tool: tiles from different instants side by side, and a queue growing faster than the canvas could drain it. Each message to the webview is a script evaluation on its main thread plus a round trip, and IronRDP will not drop a tile either — a dropped diff is a hole — so once the queue was full its session loop blocked and the server's frames stacked up behind it. Now the backend keeps its own framebuffer, applies tiles as they come, and sends what changed only after the picture has been still for 3 ms, capped at 50 ms, as one message. The webview acknowledges each message it paints and at most two are ever in flight, so under load the picture updates less often but is never behind, which is how Microsoft's own client behaves.
- **The cursor is drawn locally** — IronRDP was already sending the server's pointer shapes as events, and they were being dropped. ## v0.6.4
- **Compress and extract from the file explorer** — Right-click a file or folder in the remote explorer and there is now an Archive group: extract it if it is an archive, or compress it as `.tar.gz`, `.tar.bz2`, `.tar.xz`, `.tar.zst` or `.zip`. The work happens over SSH on the machine the files are on, because pulling a directory down to compress it and pushing it back would be absurd. The hard part is that the tools are usually not all there: `zip` is missing from most minimal images, and a naive check would put a dead menu item in front of half our users. So each operation has an ordered list of ways to do it and takes the first the machine can manage — `zip`, then `bsdtar`, then 7-Zip under whichever of its three names is installed, then a short Python script. The test for this does not hunt for stray metacharacters, which would trip over our own `cd && tar`; it asserts that the command built for a hostile name is structurally identical to one built for a dull name, differing only inside the quotes.

- **macOS: Cmd+V works in every field again** — The other half of #47. On macOS, Cmd+C and Cmd+V are menu key equivalents: the system finds the menu item bound to them and runs its selector. Said honestly: this is the least certain of the three, having been diagnosed without a Mac to measure on; the mechanism matches the report and the change is cheap, and the reporter is the test.

Right the first time, tiresome the fiftieth, and there was no way out. ## v0.5.6
- **Keys you import, not keys you copy** — Reported by [steve3d](https://github.com/steve3d) in #46: with several machines and no wish to copy `~/.ssh` onto each of them, a session could only name a key file *path*, and a path means nothing on a laptop that has never seen the file. A private key can now be imported into the vault instead — encrypted at rest, and carried to every machine by the same personal sync that already carries your sessions — with the session pointing at it by id. Import takes a paste or a file; the file is read in Rust, so key material never passes through the interface, and the only direction it moves is disk to vault. The key is parsed before it is saved, so a public key pasted by mistake, or a passphrase that does not open the key, is refused there and then rather than on your next connection attempt. The passphrase belongs to the key rather than the session: save it once and every session using that key connects without asking again. Each key shows its algorithm and SHA-256 fingerprint so two with similar names stay apart. Sessions saved before this keep their path and behave exactly as they did; the picker offers both sources, and opens on whichever the session already uses.
- **A key with no passphrase now connects** — The other half of #46, and two bugs stacked. The connect dialog treated "no saved passphrase" as "no credentials", so a key session always prompted — and the box looks like a password box, so that is what people typed. russh then handed that passphrase to `PrivateKey::decrypt`, which refuses a key that was never encrypted, and the key that would have worked failed to load. A key session now connects on the strength of naming a key, and a passphrase the key does not want is tried, discarded and forgotten instead of being fatal. The prompt appears only when the key really is locked, which is the only time it helps.
- **Imported keys are in your backups** — As key material, not as a reference: the export copies each secret's ciphertext without decrypting it and no step filters by category, so restoring on a new machine brings back keys that work, together with the sessions that use them. There is a test that walks the encoding the backup actually uses rather than trusting the code to keep doing so. Said plainly in the docs, because it cuts both ways: a backup file plus its export password recovers your private keys, since the bundle carries the vault identity key the new machine's keychain will not have.
- **A vault that has been idle can still read** — Leave Reach open long enough and it stopped loading anything — not from the server, and not from the local cache either — until it was closed and reopened. A synced vault talks to Turso over hrana, where a connection carries a baton identifying its server-side stream; the server drops a stream idle for about fifteen seconds, and the reply to the next request is an HTTP error, which libsql returns *before* the code that would clear the baton. The dead baton was then kept for the life of the process and every later request failed the same way. Not a quirk of this codebase: the same failure is filed against libsql's Rust, Go, Python and TypeScript clients, with one report putting it plainly — it "cannot be recovered from even if called again". Fixed the way every mature pool fixes it, and for the same reasons sqlx gives: connections are retired when idle and again on age, and any operation that fails is retried once on a fresh connection, so recovery is invisible rather than merely quick. The age bound covers local vaults too — a local handle cannot time out, but an I/O error can leave it failing every query when a fresh one would work, and steady use would otherwise keep a broken connection alive for as long as someone kept hitting retry.

## v0.5.2
- **Session sharing** — Share a terminal with another person, peer to peer, with no server of ours anywhere in the path. Left pane is always yours; theirs appears beside it while they share one, sized to *their* terminal rather than to the pane, because a mirror with a different column count renders every wrapped line wrong. Each side chooses what the other may do to its own terminal — read only, or read and write — and that choice is enforced on the machine that owns the terminal, never on the claim the other side makes about it. The handshake is two pastes: a code out over any chat you already trust, and a code back. The transport is the webview's own WebRTC, so there is no Rust WebRTC stack to carry. On top of DTLS, every frame is sealed with AES-256-GCM under a key derived from the share token, with direction-tagged nonces so two peers on one key can never collide, and a reply sealed with that key is the proof the guest actually had the token. Off by default, and off is absent rather than disabled: the control does not render, and the production build confirms the sharing code sits in a chunk that no entry bundle references. Turning it on loads nothing either — the first packet leaves when you click Share. Connection servers are yours: STUN defaults from two public operators, no TURN because no free public one is worth trusting, bring your own with credentials kept in the vault, or clear the list for sharing that never contacts anything outside your network. Honest limit: roughly 15–30% of NAT pairs cannot hole-punch, and those get told so, and what fixes it, instead of a silent fallback through a stranger's relay.
- **MCP server** — Expose a session you choose to an AI client over the Model Context Protocol (Streamable HTTP, JSON-RPC 2.0), bound to `127.0.0.1` only and off until you turn it on. Four agents — Linux Administrator, DevOps Engineer, DevSecOps Engineer, and a read-only Architect — set which tools a client gets, and a per-agent policy can only tighten the compiled-in guard, never loosen it; a test asserts the policy struct's field count so a permissive knob cannot be added quietly. The guard enforces rather than advises: read before write, describe before act, a lockout while terminal echo is off because someone is typing a password, a mandatory rationale, a rate limit, and a refusal for any command that carries a secret. A refusal is a tool result, never a protocol error, and a stale-view refusal hands back the output the client missed — the single largest latency win in the design. Modes — Ask, Auto (safe), Auto, and Dangerous, which runs everything and says so — are chosen from the bottom bar, per session if you like, and every setting including the token now persists in the vault rather than being regenerated on each launch. A setup wizard gives the exact connect command for eleven clients with their brand marks; each spells its config differently, and the differences were recorded from their documentation rather than guessed. - **Recipes** — Bash scripts that carry their metadata in leading `#` comments, so a recipe stays an ordinary script: `bash recipe.sh` runs it and shellcheck reads it. That matters because a recipe is arbitrary code aimed at a production server, and a format only Reach can execute is a format nobody can audit. Parameters arrive as single-quoted environment variables — the entire boundary between a value and a command. Execution is one heredoc through `bash -s`, not line-by-line typing: `set -euo pipefail` works and the exit status means something, at the cost that a recipe cannot prompt, so it takes parameters instead. A registry follows the plugin pattern with a SHA-256 pin and ships with three recipes; the test that parses them caught one understating its own risk before it shipped.

Nothing is dismissible: an indicator clears when you have been shown the thing, because a dismiss button is one more click before the feature it is pointing at. ## v0.4.2
- **Plugin hooks no longer hang SSH connect** — Loading a plugin that subscribed to `session:connected` and did slow work (e.g. `reach.http.get` to a sluggish endpoint) used to stall the entire `ssh_connect` IPC return until the plugin finished. Hook dispatch is now fire-and-forget at every call site (SSH connect/disconnect, tunnel start/stop) — IPC returns instantly, plugins run in the background. Each plugin's hook is wrapped in `tokio::time::timeout` (default 5 s, manifest-overridable via `hook_timeout_ms`, hard-capped at 30 s); on timeout or error the plugin flips to `Error` status and a toast surfaces which plugin misbehaved.
- **Luau interrupt cap for runaway plugin code** — A `while true do end` in a plugin no longer starves the runtime. The sandbox now installs a Luau interrupt callback that aborts the VM if execution exceeds 10M interrupt ticks per call, with a backup wall-clock timeout for awaits.
- **Plugin HTTP client now has a 30 s request timeout** — `reach.http.get/post` previously used `reqwest::get()` with no timeout; a stuck server could hang a plugin indefinitely. Replaced with a shared `OnceLock<reqwest::Client>` built with `.timeout(30s)`.
- **Plugin permissions re-prompt on version upgrade** — `PluginConfig` now stamps `version_at_grant` when permissions are granted; on load, if the manifest version differs, granted permissions are cleared so the user must re-confirm what the new version is allowed to do. Stored permissions are also intersected with what the manifest currently declares (stale permissions auto-dropped).
- **Plugin marketplace** — New "Marketplace" tab in the Plugins panel. Fetches a registry JSON (default `alexandrosnt/reach-plugins-registry`, override-able via `marketplace_set_url` IPC), lists available plugins with description / author / declared permissions, and installs in one click. Each install: downloads the release zip (60 s timeout, 16 MB hard cap), verifies SHA-256 against the registry entry, extracts to a staging dir with zip-slip + symlink protections, validates `plugin.toml` is at the root, then atomic-renames into `~/.reach/plugins/{id}/` and loads the plugin disabled. Trust model: the user owns the registry repo and merges PRs to admit plugins; that merge is the gatekeeping action.
  - `zip = "2.3"` pinned to avoid CVE-2025-29787 (symlink-based path traversal in older zip crate releases).
  - Defense-in-depth in `extract_zip_safely`: rejects any `is_symlink()` entry outright, validates each path via `enclosed_name()`, then canonicalizes the parent and confirms it `starts_with(staging_root)`.
- **Shared `<Button>` defaults to `type="button"`** — Bare `<button>` elements inside a `<form>` default to `type="submit"`. Previously the shared Button component had no `type` set, so any `<Button onclick={...}>` placed inside a form (e.g. the SSH key Browse picker added in v0.4.1) would also submit the surrounding form on click. Defaulted to `"button"`; submit behavior is now opt-in via the new `type` prop.

## v0.4.1
- **Terminal width fix on tab switch** — Fixes a bug where switching away from a tab with active output and back left the terminal rendering in a ~2-character-wide stripe. Root cause: `FitAddon.fit()` clamps to its 2×1 minimum when called against a `display:none` container; the ResizeObserver would fire on the hidden tab and resize the remote PTY to 2 columns, baking CRLF-wrapped 2-char lines into the buffer that couldn't be reflowed back. Particularly noticeable with TUIs that use full terminal width — though TUIs like htop self-heal on SIGWINCH and previously masked the bug; plain stream commands (`yes`, `tail -f`) showed the damage clearly.

## v0.4.0
- **OpenSSH-style cascading auth** — SSH connect now tries methods in OpenSSH order: configured key → ssh-agent identities → password. The first method the server accepts wins. Replaces the previous one-method-only model where you had to pick the right auth upfront and re-edit the session if it failed.
- **SSH agent integration** — Reach now talks to the local SSH agent and tries every loaded identity. On Windows, connects to OpenSSH's `\\.\pipe\openssh-ssh-agent` named pipe with Pageant as fallback; on Unix uses `SSH_AUTH_SOCK`. If the configured key gets rejected, every agent identity is offered to the server before giving up — same behavior as `ssh user@host` from a terminal.
- **Password fallback prompt** — when the configured key and every agent identity get rejected, the connect modal stays open and shows a password input ("Key was rejected by the server. Enter your password to try again.") instead of failing outright. Type the password, click "Try with password", connection retries with password auth.
- **Tab keyboard focus on switch** — switching SSH tabs via Ctrl+Tab or mouse click now auto-focuses the terminal so you can type immediately. Cross-platform: same behavior on Windows WebView2, macOS WebKit, Linux WebKitGTK.
- **`~` path expansion for SSH keys** — `~/.ssh/id_ed25519` in the key path field now resolves to the user's home directory on Windows / macOS / Linux. Whitespace is also trimmed so trailing spaces don't break key loads.
- **AuthParams refactored to a flat struct** — replaces the three exclusive `Password | Key | Agent` enum variants with optional fields (`key`, `password`, `allow_agent`). One `cascade_authenticate` function used by both direct and jump-host paths — no duplicated auth logic.
